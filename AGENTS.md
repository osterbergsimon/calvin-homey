# Agent instructions: calvin-homey

A Homey Pro app that shows Calvin's wall screens as Homey devices. Start with the
[design](docs/superpowers/specs/2026-11-20-homey-app-design.md) and the
[plan](docs/superpowers/plans/2026-11-20-homey-app.md); the design records what was decided and
the plan says how to build it, part by part.

## Stack

- Homey Apps SDK v3, Homey Pro only (`"platforms": ["local"]`), `"compatibility": ">=12.9.0"`
  (Node.js 22 on every Homey Pro).
- TypeScript, compiled by `homey app build` into `.homeybuild/`. Homey Compose: edit
  `.homeycompose/` and `drivers/*/*.compose.json`, never the generated `app.json`.
- App id `xyz.wholab.calvin`. It can never change after the first install; do not touch it.
- The `homey` module is provided by the Homey at runtime. Unit tests use a stub of it, never the
  real one.

## Checks

Run before every push (the plan's Part 1 adds these scripts; until then there is only Markdown):

```bash
npm ci
npm run lint            # ESLint
npm run typecheck       # tsc --noEmit
npm test                # unit tests: mocked Homey, fake Calvin
npx homey app validate --level debug
scripts/check-commit-attribution.sh origin/main..HEAD
```

CI runs the same on every pull request. Markdown changes: check that every link resolves.

## Rules

- **Public repository.** Everything here is world-readable. No hostnames, IP addresses, home
  paths, device names, screen ids, keys or other data from any real household, in code, tests,
  fixtures, docs, commits or pull requests. Use `calvin.example`, `192.0.2.x` (RFC 5737) and
  made-up screen ids such as `kitchen-000000` in examples and tests.
- **No AI attribution.** No `Co-Authored-By` lines for tools, no "Generated by", no agent, tool
  or model names in commits, pull requests, code comments or docs.
  `scripts/check-commit-attribution.sh` checks commits.
- **Never contact a real Homey or a real Calvin server** from tests, scripts or CI. Tests talk to a
  fake Calvin on `127.0.0.1` and a stubbed `homey` module. No test needs network access.
- **The owner tests on the real Homey.** Agents do not run `homey app run`, `homey app install`
  or `homey app publish`, and never log in to an Athom account. Each plan part that needs a real
  Homey ends with an owner step.
- **User-facing text comes from the UI spec.** Pairing views, device and capability names, flow
  card titles and hints, settings and error messages use the copy in Calvin's
  `docs/design/2026-11-20-homey-app.md` (by the Calvin design lead). Do not invent copy; if the
  spec lacks a string, ask for it.
- **The Calvin key is a secret.** Never log it, never put it in an error, a device setting, a flow
  token or a capability value, and never send it to the pairing view after it was entered.
- Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `ci:`, `chore:`). One pull request per
  plan part. Never force-push a shared branch.
